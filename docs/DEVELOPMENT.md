# Developing Due Back

Build instructions, architecture, and the honest state of each feature. The
[README](../README.md) is the overview; this is the working document.

## Interactions

On a cover in the Library:

- **Tap** opens the Book screen. It never starts a copy, so a stray tap cannot
  pull 1.5 GB onto the phone.
- **Long-press** checks the book out, or returns it. The Book screen carries the
  same action as a labelled button, so the gesture is a shortcut and never the
  only way to do anything; a first-run hint says so.
- **In the hand-arranged sort**, a four-way grip appears in each cover's
  bottom-right quadrant. Press and hold *that* and the book drags between
  shelves, with the books it displaces cascading live. Long-press anywhere else
  on the cover still means check out.

The `+` corner tab these covers used to carry was removed: it competed with the
artwork on every book in the library to serve the one action a reader takes a
few times a trip.

There is deliberately no multi-select. Packing several books for a trip is a
long-press each, which is quick enough, and a selection confirmed in one go
started every copy at once — five simultaneous reads off one USB stick, each
one's budget check blind to the other four.

## Rules worth knowing

- **Checking out needs the drive.** When the drawer is shut, covers still render
  from cached thumbnails and the check-out button puts the book **on hold**
  instead of failing. Holds copy automatically the next time the drive connects.
- **Returning works any time**, because the original is still on the USB.
- **Except** when a book is no longer on the drive — moved, renamed or deleted
  since the last scan. The phone then holds the only copy, so the app asks
  before returning it.
- **The budget** (4 GB by default) is measured against everything committed:
  what is on the phone plus what is on hold. Going over produces the "WON'T FIT"
  slip with the exact shortfall, and nothing is copied.

## Before you change anything

Short list, and every item on it is here because ignoring it has already cost
somebody a day.

- **Read `docs/STATE.md` first.** It says what is verified, what has never run
  on hardware, what is deliberately not fixed, and which traps have already
  cost a day. `CHANGES.md` is the history; `STATE.md` is the current list.
- **Search the knowledge base before debugging.** `npm run kb -- "a phrase"`,
  or with no arguments to list the headings. 120 entries of platform quirks
  that were expensive to learn once. Add to it when you learn another.
- **`npm test`, `npm run lint` and `npm run typecheck` before every commit.**
  CI runs the same three on every push to any branch. That is the whole
  automated suite — everything else is tested by hand, on a Pixel, with a real
  USB drive.
- **Never run `expo install --fix`.** It breaks dependency hoisting here.
  `npm run kb -- "expo install"` for what happened the one time it ran.
- **Install with `npx expo install <package>`**, not `npm install`, so versions
  stay matched to the SDK.
- **Routes live in `src/app/`** and nothing else does. Import navigation
  helpers from `expo-router`.
- **Never hand-edit `android/`.** It is generated by `npx expo prebuild` and is
  not committed. Native changes go through app config and the plugins in
  `plugins/`, which is also why patching `node_modules` is done there rather
  than with patch-package.
- **Device behaviour is verified only when it has actually run on a device.**
  Saying a thing works because it compiled is how two separate lock-screen
  fixes reached a phone and did nothing.

Two GitHub accounts are involved on this machine. `jcawlit` owns this

wrong account — not to nobody, which would at least be visible.

The address is GitHub’s own noreply form for the account. It attributes
properly, with the avatar and the contribution graph, and keeps a real address
out of a public history that anyone can read and anything can scrape.

**Commits made before 19 November 2026 are authored by `jacawl` and are staying
that way.** Re-authoring them means rewriting every commit SHA and force-pushing
over `main`, which would also strand every sha-stamped APK on the file server
(`dueback-<sha>.apk` would name commits that no longer exist). Not worth it.
## Running it

```sh

npx expo start          # then press a for Android, i for iOS
npm run typecheck       # app + tests
npm run lint

npm run kb saf          # search the knowledge base
```

SQLite via `expo-sqlite`.



## Development build

Expo Go is no longer enough: the app uses native modules it does not bundle.
You need a **development build** — your own debug app that loads JS from Metro.

Build it in the cloud (no local Android toolchain needed):

```sh
npx eas-cli login              # once
npx eas-cli build --profile development --platform android
```

That prints a QR code; scan it on the phone to install. Then `npx expo start`
and open the installed **Due Back** app rather than Expo Go.

Or build locally, which needs **JDK 17** and the Android SDK:

```sh
npx expo prebuild --platform android      # once, if there is no android/
npm run apk                               # build arm64 release, then publish
```

`npm run apk` is the whole thing: it finds the JDK and the SDK, builds, and
publishes. Use it rather than calling Gradle by hand — not for convenience,
but because three things about a Windows machine are traps and the script
exists to walk past all three. `scripts/build-apk.ts` explains each one at
length; briefly:

- **`JAVA_HOME` and `ANDROID_HOME` are set but invisible.** They live in the
  Windows registry, and a shell started by an editor or another tool does not
  always inherit them. Gradle then says `JAVA_HOME is not set`, which is false
  and sends you hunting. The script reads the registry when the environment is
  silent.
- **Not every JDK on the machine works.** Android Studio ships one at
  `Android Studio/jbr`, and on this machine its `lib/` is missing `jvm.cfg`, so
  `java` dies with `could not open jvm.cfg`. Having `bin/java.exe` proves
  nothing; the script checks properly and names what it rejected.
- **Two Android SDKs exist**, `C:\Android` and `%LOCALAPPDATA%\Android\Sdk`,
  holding different NDK and build-tools versions. The persisted `ANDROID_HOME`
  wins, so a build does not quietly change toolchain.

Its flags: `--debug` for a debug build, `--all-abis`, `--no-publish`.

By hand, if you must — and then **always pass `-PreactNativeArchitectures`**:

```sh
export JAVA_HOME=/path/to/jdk-17                 # must contain lib/jvm.cfg
export ANDROID_HOME=/path/to/android-sdk
cd android && ./gradlew :app:assembleRelease -PreactNativeArchitectures=arm64-v8a
```

The default builds all four CPU architectures, compiling the native modules
from source four times over: 22 minutes and a 282 MB APK, versus a few minutes
and a much smaller one. Modern phones — any recent Pixel — are `arm64-v8a`.
Use `x86_64` for an emulator. `:app:assembleDebug` is the debug equivalent.

`npm run apk:publish` is the publishing half on its own, for an APK already
built. It copies it to `dueback.apk` at the repository root, and to the file
server as both `dueback-<sha>.apk` and `dueback.apk`. The sha-stamped name
is what makes "was this broken before that change?" answerable later; the
plain one is always the newest, so the phone's bookmark never moves. Set
`APK_SHARE` to point somewhere else, and the share is skipped rather than
failed when it cannot be reached.

Installing it on a phone over USB:

```sh
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
npx expo start          # phone and computer on the same Wi-Fi
```

Then open **Due Back** on the phone; it connects to Metro over the network. A
debug build loads its JS from the dev server, so Metro needs to stay running.

`android/` is generated and git-ignored — never edit it by hand. Native
configuration lives in `app.json` and `plugins/`, and a change to either needs a
fresh build. Everything else is JS and reloads over Metro.

## How scanning works

A scan **never copies audio**. It walks the library root, groups files into
books, reads each book's metadata through byte-range reads, caches a downscaled
cover thumbnail, and writes everything to SQLite. The shelves then work with the
drive unplugged.

- **Grouping**: one folder of audio = one book. Filename-based splitting is a
  fallback for a folder that clearly holds several works.
- **Part order**: natural filename order ("Part 2" before "Part 10"), unless
  every file has a distinct track tag — then tags win, and a disagreement is
  recorded as a warning on the book.
- **Names**: embedded metadata first. The folder name is used when metadata is
  missing, or when it is a tighter version of the embedded title (which turns an
  album tag of `15 - Hyperion - Dan Simmons - 1989` into `Hyperion`). Junk like
  `[Unabridged]`, `(2019)`, `64kbps`, underscores and leading series numbers is
  stripped. The dev screen shows the raw folder name beside the result.
- **Chapters**: best effort. Embedded when they parse; otherwise one chapter per
  file for a multi-part book; otherwise none.
- **Identity**: a book's id is a hash of its path relative to the root, so a
  rescan updates rows instead of duplicating them.
- **Incremental**: a book whose files all have the same size and mtime is
  skipped. Books that vanish are flagged missing, never deleted — their progress
  and library-card history survive a drive being unplugged. Settings offers
  "Forget N missing books" when you really do want them gone.
- **Formats**: `.m4b`, `.m4a`, `.mp3`. Other audio is counted and skipped;
  ebooks and other files are ignored silently. DRM files are marked unplayable.
- **Cost**: a 1 GB `.m4b` is **164 KB in 3 reads**. File size barely matters;
  only the number of seeks does.

The awkward parts — SAF document ids, what changing the root does to book
identity, how incremental fingerprints are keyed — are in the knowledge base:
`npm run kb scanning`.

## What is real, and what is not

The library, the copy and the playback have all been run against a real
collection on a real phone, off a USB drive over OTG. `docs/STATE.md` is the
authoritative list of what that covers and what has still only been seen in
tests; the short version is below.

- Every screen, the first four matching `design/`.
- Folder picking, scanning, grouping, metadata, covers, SQLite, incremental
  rescan, missing-book handling, settings.
- **The copy is real.** It streams part by part into a staging folder, verifies
  each one's size, and only then moves the folder into place, so a half-copied
  book is never visible as a book. A cancel, a pulled drive or a failed read
  discards everything. A copy killed with the app survives as staged files and
  is resumed, part by verified part, the next time the book is checked out.
  Copies continue while the app is in the background.
- **Audio is real**, through `expo-audio` behind the `AudioEngine` interface in
  [src/lib/audio/engine.ts](../src/lib/audio/engine.ts). One player for the whole
  book, whether that is one `.m4b` or a hundred and twenty-seven `.mp3` files:
  parts are a detail the engine hides, and everything above it is expressed in
  whole-book seconds. Background playback and lock-screen controls come from a
  media-playback foreground service. The next part is preloaded as the current
  one ends, so the seam is as short as the platform allows.
- Check out / return / hold, the budget and its refusals, the warning before
  returning a book that has left the drive, the drawer-shut state.
- Chapter scrubbing, ±30 s, speed, the sleep lamp, contents, saved progress.
- **Search**, forgiving about accents and word order, matching on word prefixes
  across title, author and narrator.
- **Duplicates.** Two copies of the same book are indexed separately, because
  they are different files in different places — but the Book screen says where
  the other one lives, so nobody checks out 1.5 GB twice by accident.
- **The DRM stamp.** An Audible or FairPlay file is listed, stamped on its
  cover and refused at check-out, with a note explaining why rather than a
  failure later.
- **Phone-local libraries.** Point the app at a folder on the phone itself and
  there is nothing to plug in and nothing to check out: no corner tabs, no
  select, "Play" instead of "Check out", and no book is ever stored twice.
- **Adding a book from the phone**, by folder or single file, with an offer to
  copy it onto the drive once that is connected — after which the scan
  recognises the folder as that same book rather than indexing it again.
- **Seven sorts**: by length, by author, by series (in story order, read from
  the tags), by narrator, by what is gathering dust, by what is unfinished, and
  by hand. The hand-arranged one is dragged into place and survives a rescan;
  when a rescan re-mints ids and strands every assignment, it repairs itself
  and falls back to by-length in the meantime rather than showing bare shelves.
- **Notes, progress, listening history and shelves travel on the drive**, in
  `.dueback/`, so a second phone pointed at the same library picks up where the
  first left off. Last writer wins, per field, with a conflicted copy kept for
  a note rather than a silent overwrite.
- **Themes**, derived from one hand-tuned palette by hue and saturation
  transform rather than drawn four times over.
- **Listening statistics** — totals, local-day streaks, a fortnight of bars,
  busiest weekday, time per book — counted as wall-clock seconds with audio
  running, so a book played at 1.5× is not recorded as two thirds of the time
  it actually took.

Audiobookshelf is the one area still unproven: sign-in, library listing,
streaming, download and progress sync are all implemented and unit-tested, and
none of it has been through a full session against a real server on a phone.

Known gaps:

1. **iOS access across restarts** — `expo-file-system` calls
   `startAccessingSecurityScopedResource()` but never persists a bookmark, so a
   picked folder is lost on relaunch. Android persists its permission and is
   unaffected. Either re-pick each launch or add a small native module.
2. **No next/previous chapter on the lock screen.** `expo-audio` does not
   expose it. The skip buttons it does expose were wired as custom session
   commands the controller is told are unsupported, so they rendered and did
   nothing; `plugins/withLockScreenSeek.js` rewrites them to player commands
   and moves the jump to one minute at prebuild. Chapter navigation would need
   more than a rewrite — see `npm run kb -- "skip buttons"`.
3. The running list of smaller things lives at the end of
   [CHANGES.md](../CHANGES.md).
